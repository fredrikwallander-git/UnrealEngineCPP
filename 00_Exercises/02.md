## Exercise 2 - Custom GameMode

**Objective:** Create and wire up a custom GameMode.

1. Create `AEscapeRoomGameMode` as a C++ class inheriting from `AGameModeBase`.
2. Add a `UPROPERTY(EditDefaultsOnly) int32 TotalPuzzles = 3` and a private `int32 SolvedPuzzles = 0`.
3. Add a `UFUNCTION(BlueprintCallable) void ReportPuzzleSolved()` that:
   - Increments `SolvedPuzzles`.
   - Logs how many puzzles are solved out of total.
   - If `SolvedPuzzles >= TotalPuzzles`, calls `OnAllPuzzlesSolved()`.
4. Add a `UFUNCTION(BlueprintImplementableEvent) void OnAllPuzzlesSolved()`.
5. Set this GameMode as the active mode in World Settings.
6. In the level, add a Blueprint that calls `ReportPuzzleSolved()` three times via key presses. Implement `OnAllPuzzlesSolved` in a Blueprint child to print "Escape complete!" on screen.

Build, test.

## Exercise 6 - Line Trace and Focus

**Objective:** Wire up the character so pressing E interacts with whatever the player is looking at.

In your Character:

1. Add `UPROPERTY() TObjectPtr<UInteractableComponent> FocusedInteractable`.
2. Add `UPROPERTY(EditDefaultsOnly, Category = "Interaction") float InteractRange = 250.0f`.
3. In `Tick`, run a line trace from the camera forward. Use `ECC_Visibility`. Ignore self. On hit, call `FindComponentByClass<UInteractableComponent>()` on the hit actor and store in `FocusedInteractable`. Clear `FocusedInteractable` at the start of each tick.
4. In `Interact()`, call `FocusedInteractable->Interact(this)` if valid and enabled.
5. Enable `PrimaryActorTick.bCanEverTick = true` in the Character constructor if it is not already.

Build. Walk up to the door. Press E. The door should log "Door opened".

**Debug:** Add a `DrawDebugLine` call in Tick to visualise the line trace. Take a screenshot of the line visible in Play mode. This is the `LineTraceDebug.png` for the Screenshot Guide.

## Exercise 7 - A Second Interactable: Key Pickup

**Objective:** Prove the component is genuinely reusable.

Create a `AKeyPickup` actor class. Requirements:

1. A `UStaticMeshComponent` as root.
2. A `UInteractableComponent` added in the constructor.
3. A `UPROPERTY(EditAnywhere) FName KeyId = "DefaultKey"`.
4. In `BeginPlay`, bind to `OnInteracted`. Set the prompt to "Pick up key".
5. The callback should:
   - Log the key ID.
   - Disable the component (`bIsEnabled = false`) so it cannot be picked up twice.
   - Hide the actor (`SetActorHiddenInGame(true)`).
   - Disable collision (`SetActorEnableCollision(false)`).

Build. Place a `AKeyPickup` in the level near the door. Walk up and press E on the key. Confirm it logs and disappears. Then walk to the door and press E. Confirm the door logs.

The player code has not changed at all. The same E key, the same line trace, the same component, a completely different actor responded differently.

## Exercise 8 - Blueprint Event Binding

**Objective:** Bind to `OnInteracted` from a Blueprint graph, not from C++.

Create a Blueprint Actor called `BP_LightSwitch`. Do not give it a C++ parent class (use plain `AActor`).

In the Blueprint:

1. Add an `Interactable Component` from the Components panel.
2. In the Event Graph, use `BeginPlay > Get InteractableComp > Bind Event to On Interacted`.
3. In the bound event, toggle a `Point Light` component between on and off.
4. Set the `Interact Prompt` text on the component to "Toggle Light".

Place `BP_LightSwitch` in the level. Walk up and press E. The light should toggle. No C++ changes needed.

This is the full power of the pattern: C++ defines the component and the delegate. Blueprint composes behaviour from it without any C++ subclassing.
