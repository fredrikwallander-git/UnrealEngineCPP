# 06 - C++ Interfaces - Exercises

## Exercise 1 - Declare the Interface

**Objective:** Create an Unreal C++ interface and understand its two-class structure.

1. Create a new header file `IInteractable.h` in `Source/EscapeRoomLab/Public/`. Do not use the New C++ Class wizard for this one. Create the file manually in the IDE.
2. Declare both classes: `UInteractable` (the Unreal boilerplate class) and `IInteractable` (the interface you actually use).
3. Add three functions to `IInteractable`, all `BlueprintNativeEvent` and `BlueprintCallable`:
    - `void Interact(AActor* Interactor)`
    - `FText GetInteractPrompt() const`
    - `bool CanInteract() const`
4. Build. Fix any errors.

**Ask yourself:** Why are there two classes (`UInteractable` and `IInteractable`) when standard C++ interfaces only need one? What does each class do?

## Exercise 2 - Implement on a Test Actor

**Objective:** Implement the interface on a simple actor and call it correctly.

1. Create a new C++ Actor class `ATestInteractable`.
2. Add `public IInteractable` to its inheritance.
3. Declare and implement all three `_Implementation` functions:
    - `Interact` logs "TestInteractable interacted by [actor name]".
    - `GetInteractPrompt` returns `FText::FromString(TEXT("Test Interact"))`.
    - `CanInteract` always returns `true`.
4. Build. Place `ATestInteractable` in the level.
5. In a temporary Blueprint (or key press in the character), use `Execute_Interact` to call the interface function on the placed actor. Confirm the log fires.

**Note:** When calling from Blueprint, the interface functions appear as callable nodes once the actor implements the interface. When calling from C++, always use `Execute_` rather than `_Implementation` directly when the target might be a Blueprint class.

## Exercise 3 - Implements Check

**Objective:** Understand how to detect interface implementation at runtime.

1. In the character's Tick, temporarily replace the `FindComponentByClass` call with an `Implements<UInteractable>()` check on the hit actor.
2. Store the hit actor in a temporary `TObjectPtr<AActor> TempFocused` variable.
3. In a temporary version of `Interact()`, call `IInteractable::Execute_CanInteract(TempFocused)` and `IInteractable::Execute_Interact(TempFocused, this)`.
4. Test against the `ATestInteractable` from Exercise 2. Confirm interaction works.
5. Test against a plain `AStaticMeshActor` (one that does not implement the interface). Confirm nothing fires.

**Reflect:** What is the difference between `Cast<IInteractable>(Actor)` and `Actor->Implements<UInteractable>()`? When would you prefer one over the other?

## Exercise 4 - Blueprint Implementation

**Objective:** Implement the interface on a Blueprint-only actor with no C++ parent.

1. Create a new Blueprint Actor (not from a C++ class). Name it `BP_LightSwitch`.
2. In Class Settings, under Implemented Interfaces, add `Interactable`.
3. Implement `Interact` in the Blueprint Event Graph. Toggle a Point Light component on and off.
4. Implement `GetInteractPrompt` to return "Toggle Light".
5. Implement `CanInteract` to return `true`.
6. Place `BP_LightSwitch` in the level next to `ATestInteractable`.
7. Confirm the character's Tick detects and interacts with both using the same `Implements<UInteractable>()` check.

**Reflect:** The C++ actor and the Blueprint actor both implement the same interface. The character code that calls them is identical. What does this tell you about the interface pattern's value for a mixed C++/Blueprint project?
