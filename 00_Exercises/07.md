# 07 - Data Assets and Configuration - Exercises

These exercises shift configuration out of Blueprint class defaults and into standalone assets. The goal is a project where a designer can add a new puzzle or item by creating an asset and filling in a form, with no Blueprint or C++ changes needed.

---

## Exercise 1 - Your First Data Asset

**Objective:** Create a data asset class and an instance of it in the editor.

1. Create a C++ class `UPuzzleData` inheriting from `UDataAsset`. Mark it `UCLASS(BlueprintType)`.
2. Add the following properties, all `EditAnywhere BlueprintReadOnly`:
    - `FName PuzzleId`
    - `FText DisplayName`
    - `FName NarrativeEventOnSolve`
    - `bool bResetOnFailure = true`
3. Build. In the Content Browser, create a folder called `Data`. Right-click inside it, go to **Miscellaneous > Data Asset**, select `UPuzzleData`, and name it `DA_TestPuzzle`.
4. Open `DA_TestPuzzle`. Fill in all the fields.
5. Create a second asset `DA_TestPuzzle_B` with different values.

**Reflect:** What is the practical difference between editing values here versus editing them on a Blueprint class default? What can a designer do with a data asset that they cannot do as easily with Blueprint class defaults?

## Exercise 2 - Assign the Asset to a Puzzle

**Objective:** Replace inline configuration on a puzzle actor with a data asset reference.

1. Open `APuzzleBase`. Add `UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Puzzle") TObjectPtr<UPuzzleData> PuzzleData`.
2. Include `PuzzleData.h` in `PuzzleBase.h`.
3. In `APuzzleBase::OnSolved_Implementation`, if `PuzzleData` is valid, fire the narrative event using `PuzzleData->NarrativeEventOnSolve` instead of the hardcoded `"PuzzleSolved"` string.
4. Build. Open a placed puzzle Blueprint child in the level. Assign `DA_TestPuzzle` to the `Puzzle Data` property in the Details panel.
5. Play through to the solve. Confirm the narrative event name in the Output Log matches what you set in the asset.

**Ask yourself:** If you have five puzzles in the level and want to change the narrative event name for puzzle three, how many files do you open with this approach versus the old hardcoded approach?

## Exercise 3 - Extend for Sequence Puzzle

**Objective:** Move the correct sequence out of the Blueprint class default into the data asset.

1. Add to `UPuzzleData`:
    - `TArray<FName> CorrectSequence` (`EditAnywhere BlueprintReadOnly`)
2. Build. Update `DA_TestPuzzle` with a three-step sequence.
3. In `ASequencePuzzle::Activate`, check for `PuzzleData` before reading `CorrectSequence`. If `PuzzleData` is valid, use `PuzzleData->CorrectSequence`. If not, fall back to the existing inline `CorrectSequence` property.
4. Test the sequence puzzle. Confirm it reads the sequence from the asset.

**Note:** The fallback to the inline property is good defensive programming. A puzzle without an assigned data asset should still work, just with whatever was configured directly on the Blueprint.

## Exercise 4 - Define the Item Row Struct

**Objective:** Create a `FTableRowBase` struct for item data.

1. Create a new header `ItemData.h` in `Source/EscapeRoomLab/Public/`. Define a `USTRUCT(BlueprintType)` called `FItemData` inheriting from `FTableRowBase`.
2. Add at minimum:
    - `FText DisplayName` (`EditAnywhere BlueprintReadWrite`)
    - `FText Description` (`EditAnywhere BlueprintReadWrite`)
    - `bool bIsConsumable = false` (`EditAnywhere BlueprintReadWrite`)
3. Build. In the Content Browser under `Data/`, right-click > **Miscellaneous > Data Table**, select `FItemData` as the row struct, name it `DT_Items`.
4. Open `DT_Items`. Add at least two rows:
    - Row name `BrassKey`: fill in display name and description.
    - Row name `IronKey`: fill in different values.
5. Export the table to CSV (**right-click > Export as CSV**). Open the CSV in a text editor or spreadsheet application. Confirm the structure.

**Reflect:** Why does the row name match the `FName` values already used in the inventory system? What makes this convenient?

## Exercise 5 - Read from the Data Table

**Objective:** Look up item data at runtime using the inventory system.

1. In `AEscaperoomLabCharacter`, add `UPROPERTY(EditDefaultsOnly, Category = "Data") TObjectPtr<UDataTable> ItemTable`.
2. Include `Engine/DataTable.h` and `ItemData.h`.
3. Add a `UFUNCTION(BlueprintCallable) FItemData GetItemData(FName ItemId) const`. In the implementation, call `ItemTable->FindRow<FItemData>(ItemId, TEXT("GetItemData"))`. Return the dereferenced row if found, or a default `FItemData` if not.
4. In `BP_ThirdPersonCharacter` class defaults, assign `DT_Items` to `Item Table`.
5. In a temporary Blueprint event (key press), call `GetItemData` passing `"BrassKey"`. Print the `Display Name` result. Confirm it matches what you entered in the table.

**Note on the return type:** `FItemData` is returned by value, not pointer. This is intentional. The `FindRow` raw pointer is only valid while the table asset is loaded. Returning a copy is safer for general use.

## Exercise 6 - Drive the HUD Inventory Display

**Objective:** Show item display names in the HUD instead of just a count.

1. In `UEscapeRoomHUD`, replace `UpdateInventoryCount(int32 Count)` with `UpdateInventoryDisplay(const TArray<FName>& ItemIds, UDataTable* ItemTable)`.
2. In the implementation, build an `FString` listing the display name of each item using `FindRow`. Fall back to the raw `FName` string if no row is found for an item.
3. Set `InventoryCountText` (or a new `InventoryListText` if you prefer) to display the result.
4. Update the character's Tick to call the new function, passing `Inventory` and `ItemTable`.
5. Pick up the brass key in the level. Confirm the HUD shows the display name rather than just a count.

## Exercise 7 - Designer Workflow Test

**Objective:** Prove the system works without code changes.

Without touching any C++ or Blueprint graph:

1. Add a new row to `DT_Items` called `CopperKey` with its own display name and description.
2. Create a new `AKeyPickup` Blueprint in the level with `KeyId` set to `CopperKey`.
3. Create a new `UPuzzleData` asset `DA_CopperDoor` with a different `RequiredKeyId` of `CopperKey`.
4. Place a new door in the level and assign `DA_CopperDoor` to its puzzle.
5. Play. Pick up the copper key. Confirm the HUD shows its display name. Use it on the door. Confirm the puzzle solves.

If the above works without any code or Blueprint graph changes, the data layer is correctly separated from the logic layer.
