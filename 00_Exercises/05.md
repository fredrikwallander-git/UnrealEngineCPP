# 05 - UMG and UI - Exercises

## Exercise 1 - Add UMG to the Build

**Objective:** Understand that UI requires explicit module dependencies.

1. Open `EscapeRoomLab.Build.cs`. Add `"UMG"` and `"Slate"` to `PublicDependencyModuleNames`.
2. Build. Confirm it compiles cleanly.
3. In a temporary cpp file, add `#include "Blueprint/UserWidget.h"` and confirm it resolves. Remove the temp include after confirming.

**Reflect:** Why does UMG need to be listed in `Build.cs` separately from the rest of the engine? What would happen if you tried to use `UUserWidget` without adding it?

## Exercise 2 - Your First User Widget

**Objective:** Create a C++ widget class and display it on screen.

1. Create a C++ class inheriting from `UUserWidget`. Name it `EscapeRoomHUD`. Do not add any `BindWidget` properties yet.
2. Override `NativeConstruct`. Add a `UE_LOG` so you can confirm when it fires.
3. In `AEscaperoomLabCharacter`, add:
    - `TSubclassOf<UUserWidget> HUDWidgetClass`, `EditDefaultsOnly`.
    - `TObjectPtr<UUserWidget> HUDWidget`, `UPROPERTY()` only.
4. In `BeginPlay`, create the widget using `CreateWidget` and call `AddToViewport`.
5. Build. Create a Widget Blueprint child of `UEscapeRoomHUD`. Name it `WBP_HUD`. Add any visible element to it (a simple Text Block saying "HUD active").
6. Assign `WBP_HUD` to `HUDWidgetClass` in `BP_ThirdPersonCharacter`'s class defaults. Play. Confirm the widget appears on screen and the `NativeConstruct` log fires.

**Ask yourself:** If `CreateWidget` is called but `HUDWidgetClass` is null (not assigned), what happens? What should you guard against?

## Exercise 3 - BindWidget and the Interact Prompt

**Objective:** Connect C++ data to a named widget element.

1. In `UEscapeRoomHUD`, add:
    - `UPROPERTY(meta = (BindWidget)) TObjectPtr<UTextBlock> InteractPromptText`
    - `UPROPERTY(meta = (BindWidget)) TObjectPtr<UWidget> InteractPromptContainer`
    - A `void UpdateInteractPrompt(const FText& Prompt, bool bVisible)` function.
2. Implement `UpdateInteractPrompt`:
    - Set `InteractPromptText` text.
    - Set `InteractPromptContainer` visibility using `ESlateVisibility::Visible` / `Hidden`.
3. In `WBP_HUD`, open the UMG designer. Add a widget (Border or Vertical Box) named exactly `InteractPromptContainer`. Inside it, add a Text Block named exactly `InteractPromptText`. Anchor the container at the bottom centre.
4. Open the Widget Blueprint's graph. Confirm the binding warnings are gone (both widgets found by name).
5. In `AEscaperoomLabCharacter::Tick`, after the line trace, cast `HUDWidget` to `UEscapeRoomHUD` and call `UpdateInteractPrompt` with the focused interactable's `InteractPrompt` text and a visibility bool.
6. Build. Walk up to the door. Confirm the prompt appears and disappears correctly.

**Troubleshooting:** If the prompt is always hidden or always visible, check that the cast in Tick succeeds (add a log). If the cast fails, verify the Widget Blueprint parent class is `UEscapeRoomHUD` and not plain `UserWidget`.

## Exercise 4 - Inventory Display

## Exercise 5 - UWinScreen

**Objective:** Build a win state widget that the game can trigger.

1. Create a C++ class `UWinScreen` inheriting from `UUserWidget`.
2. Add:
    - `UPROPERTY(meta = (BindWidget)) TObjectPtr<UTextBlock> WinMessageText`
    - `UPROPERTY(meta = (BindWidget)) TObjectPtr<UButton> QuitButton`
    - `void Show()`
    - `UFUNCTION() void OnQuitClicked()`
    - Override `NativeConstruct`
3. In `NativeConstruct`, bind `QuitButton->OnClicked` to `OnQuitClicked` using `AddDynamic`.
4. In `Show`, call `AddToViewport(10)`, set visibility to `Visible`, and set the win message text.
5. In `OnQuitClicked`, call `UKismetSystemLibrary::QuitGame`. Include `Kismet/KismetSystemLibrary.h`.
6. Create `WBP_WinScreen` as a Widget Blueprint child of `UWinScreen`. Add a Text Block named `WinMessageText` centred on screen. Add a Button named `QuitButton` below it with a "Quit" label.
7. Test by calling `Show()` from a temporary key press in the character. Confirm the screen appears and the quit button works.

**Note on UButton:** `UButton` is in the `"UMG"` module. Its `OnClicked` delegate is `FOnButtonClickedEvent` — a `DYNAMIC_MULTICAST_DELEGATE` that takes no parameters. The `AddDynamic` callback must match that signature: `void OnQuitClicked()` with no parameters.

## Exercise 6 - TriggerWin on the GameMode

**Objective:** Connect puzzle completion to the win screen through the GameMode.

1. In `AEscapeRoomGameMode`, add:
    - `TSubclassOf<UWinScreen> WinScreenClass`, `EditDefaultsOnly`.
    - `UFUNCTION(BlueprintCallable) void TriggerWin()`.
2. Implement `TriggerWin`:
    - Get the first `APlayerController`.
    - Create the `UWinScreen` widget using `CreateWidget<UWinScreen>`.
    - Call `Show()` on it.
    - Call `PC->SetInputMode(FInputModeUIOnly())`.
    - Set `PC->bShowMouseCursor = true`.
3. In the GameMode Blueprint child's class defaults, assign `WBP_WinScreen` to `WinScreenClass`.
4. In `ANarrativeDirector`'s `OnNarrativeLine` Blueprint implementation, add a branch: if `EventId == "EscapeComplete"`, cast `GetGameMode` to your GameMode class and call `TriggerWin`.
5. On your final puzzle (`ASequencePuzzle` or `AKeyPuzzle`), add a `NarrativeTriggerComponent` and fire `"EscapeComplete"` from `OnSolved_Implementation` (override in the Blueprint child or add to the C++ `OnSolved`).
6. Play through the full puzzle chain. Confirm the win screen appears after the last puzzle is solved.

## Exercise 7 - Polish the HUD

**Objective:** Make the UI feel intentional rather than placeholder.

Pick at least two of the following and implement them:

1. **Fade the interact prompt.** Instead of showing/hiding instantly, animate the `InteractPromptContainer` opacity using a `WidgetAnimation` in the Widget Blueprint. Trigger it from `NativeConstruct` or from a Blueprint function called by `UpdateInteractPrompt`.
2. **Crosshair.** Add a small crosshair image centred on screen in `WBP_HUD`. Show it always. It does not need to change state.
3. **Inventory item icons.** Instead of just a count, show a horizontal box of small icons (use any texture) for each item in `Inventory`. Update it from `UpdateInventoryCount` or add a new `UpdateInventoryItems(const TArray<FName>& Items)` function.
4. **Win screen animation.** Add a `WidgetAnimation` in `WBP_WinScreen` that fades the screen in over 1 second. Call `PlayAnimation` from `NativeConstruct` or from `Show`.
5. **Contextual prompt icon.** Show a different icon alongside the interact prompt based on the `InteractPrompt` text or a new `EInteractType` enum on the component.
