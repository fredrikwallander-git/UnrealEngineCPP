# 01 - Fundamentals - Exercises

Work through these in order. Each exercise builds on the previous one. All code goes in your `EscapeRoomLab` project and is pushed to your GitHub repository at the end of each session.

Do not look at the `LiveCodingGuide.md` unless you are well and truly stuck. Struggling with a problem for 15 minutes before looking at a solution is normal and useful. Struggling for 45 minutes without making any progress is not.

---

## Exercise 1 - Create Your First C++ Actor

**Objective:** Get comfortable with the new C++ class workflow.

1. In the Unreal editor, go to **Tools > New C++ Class > Actor > Public**. Name it `PickupBase`.
2. Build the project.
3. Open `PickupBase.h` and identify without looking anything up:
   - Which line marks this class for the reflection system?
   - Which macro is required for the reflection system to work correctly?
   - What does the `A` prefix on `APickupBase` mean?
4. In `PickupBase.cpp`, add a `UE_LOG` call inside `BeginPlay` that prints the actor's name using `GetName()`.
5. Build, place a `PickupBase` in the level, press Play. Confirm the log message appears in the Output Log.

## Exercise 2 - Adding Properties

**Objective:** Use `UPROPERTY` specifiers correctly.

Add the following to `APickupBase`:

1. A `FName PickupId` that is `EditAnywhere` and `BlueprintReadOnly`, in a category called `"Pickup"`. Set a default value of `"Unnamed"`.
2. A `bool bIsCollected` that is `VisibleAnywhere` and is not editable. Default `false`.
3. A `float RespawnDelay` that is `EditDefaultsOnly`, with a `ClampMin` of `0.0` and `ClampMax` of `60.0`, default `5.0`. Category `"Pickup|Respawn"`.
4. A `TObjectPtr<UStaticMeshComponent>` called `MeshComp`, created in the constructor with `CreateDefaultSubobject`, set as `RootComponent`, and marked `VisibleAnywhere`.

Build and place two instances of `APickupBase` in the level. In the Details panel:

- Change `PickupId` on one instance. Confirm it only changes that instance.
- Try to change `RespawnDelay` on the instance. What happens and why?
- Confirm `bIsCollected` is visible but read-only in the editor.

## Exercise 3 - Adding Functions

**Objective:** Use `UFUNCTION` correctly and understand the difference between the three Blueprint exposure types.

Add the following to `APickupBase`:

1. A `UFUNCTION(BlueprintCallable, Category = "Pickup") void Collect(AActor* Collector)` that:
   - Returns early if `bIsCollected` is already true.
   - Sets `bIsCollected = true`.
   - Logs the Collector's name and the `PickupId`.
   - Calls `OnPickupCollected()`.

2. A `UFUNCTION(BlueprintImplementableEvent, Category = "Pickup") void OnPickupCollected()`. No cpp body.

3. A `UFUNCTION(BlueprintPure, Category = "Pickup") bool IsAvailable() const` that returns `!bIsCollected`.

Build. Create a Blueprint child of `APickupBase`. In the Blueprint Event Graph, implement `OnPickupCollected` to print a screen message using Print String. Place the Blueprint in the level. Play and call `Collect` on it through the Blueprint graph using a Key press node.

Confirm `OnPickupCollected` fires in the Blueprint and the log message appears.

**Bonus:** Make a second Blueprint child that implements `OnPickupCollected` differently (plays a particle, changes a material, anything visible). Place both in the level and confirm they each do their own thing.

## Exercise 4 - Garbage Collection and Pointers

**Objective:** Understand when to use `UPROPERTY()` for GC safety.

In `APickupBase`:

1. Add a `UPROPERTY() TObjectPtr<AActor> LastCollector`. This stores who last collected this pickup.
2. Add a raw pointer `AActor* UnsafeCollector` without `UPROPERTY`. Add a comment explaining what risk this introduces.
3. In `Collect`, set both `LastCollector` and `UnsafeCollector` to the `Collector` parameter.
4. Add a `UFUNCTION(BlueprintCallable) FString GetLastCollectorName() const` that:
   - Returns `"None"` if `LastCollector` is null.
   - Returns `LastCollector->GetName()` otherwise.

Build. Think through and write a short comment in the code answering: under what circumstances would `UnsafeCollector` become a dangling pointer but `LastCollector` would not?

## Exercise 5 - Containers and Strings

**Objective:** Use `TArray`, `TMap`, and the three string types in a meaningful context.

Create a new C++ Actor class called `KeyRing`. It represents an actor that holds a collection of keys the player has found.

Requirements:

1. A `TArray<FName> CollectedKeys`, `VisibleAnywhere`.
2. A `TMap<FName, int32> KeyUsageCount`, not exposed to the editor (just `UPROPERTY()` for GC).
3. A `UFUNCTION(BlueprintCallable) void AddKey(FName KeyId)` that:
   - Does nothing if the key is already in `CollectedKeys`.
   - Adds `KeyId` to `CollectedKeys`.
   - Adds the key to `KeyUsageCount` with value `0`.
   - Logs an `FString` built with `FString::Printf` that says which key was added.
4. A `UFUNCTION(BlueprintCallable) bool HasKey(FName KeyId) const` that returns true if `CollectedKeys` contains the key.
5. A `UFUNCTION(BlueprintCallable) void UseKey(FName KeyId)` that increments the usage count for that key.
6. A `UFUNCTION(BlueprintPure) FText GetKeyCountDisplay() const` that returns an `FText` showing the number of keys held, formatted as `"Keys: 3"`.

Build. In `BeginPlay`, add two keys and log the display text. Confirm in the Output Log.

Write one sentence explaining why `KeyId` is `FName` rather than `FString`.

## Exercise 6 - The Door Worked Example

**Objective:** Build the full door from the README.

This is the capstone exercise for block 01. Build the `ADoor` class described in the README from scratch.

Requirements (from the README):

- `UStaticMeshComponent` as root.
- `bool bIsLocked`, `EditAnywhere`, `BlueprintReadWrite`, default `false`.
- `float OpenAngle`, `EditDefaultsOnly`, `ClampMin = 0`, `ClampMax = 180`, default 90.
- `float OpenDuration`, `EditAnywhere`, `BlueprintReadWrite`, default 1.5.
- `FName RequiredKeyId`, `EditAnywhere`.
- `TArray<FName> KeysHeld`. Populate with one test key in `BeginPlay`.
- `BlueprintCallable bool TryOpen()` function. Returns true and logs "Door opened" if unlocked. Returns false otherwise.
- `BlueprintImplementableEvent void OnDoorOpened()`. Called by `TryOpen()` on success.

After building, create a Blueprint child. Implement `OnDoorOpened` to do something visible. Place the Blueprint in the level. Call `TryOpen()` from a key press in the Blueprint graph and confirm it works.
