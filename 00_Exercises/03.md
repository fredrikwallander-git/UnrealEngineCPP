# 03 - Timelines and Narrative - Exercises

## Exercise 1 - Animate the Door

**Objective:** Make the Door from block 02 rotate smoothly using a Timeline.

1. In the Content Browser, create a `CurveFloat` asset called `C_DoorOpen`. Add two keyframes: (0.0, 0.0) and (1.5, 1.0). Set both to Cubic (Auto) interpolation. Save.
2. Add a `FTimeline OpenTimeline` member to `ADoor`. Add a `TObjectPtr<UCurveFloat> OpenCurve` property (`EditDefaultsOnly`). Add `UFUNCTION() void TimelineUpdate(float Value)` and `UFUNCTION() void TimelineFinished()`.
3. Enable tick on the door constructor (`PrimaryActorTick.bCanEverTick = true`).
4. In `BeginPlay`, bind the curve to the timeline using `AddInterpFloat` and `BindUFunction`.
5. In `Tick`, call `OpenTimeline.TickTimeline(DeltaTime)`.
6. In `TimelineUpdate`, calculate the new rotation using the current closed rotation plus `Value * OpenAngle` on the Yaw axis. Apply with `SetRelativeRotation`.
7. In `OnInteracted`, call `OpenTimeline.PlayFromStart()` instead of just logging.
8. Build. Assign `C_DoorOpen` to the Door Blueprint's `OpenCurve` property. Play. Walk up to the door and press E.

**Verify:** The door rotates smoothly over ~1.5 seconds. It does not snap. Pressing E again while it is open or moving does nothing (because `bIsOpen` is already true).

**Tweak exercise:** Change the curve keyframe at (1.5, 1.0) to (0.8, 1.0) and play again. What changes? Try setting both keys to Linear interpolation. What changes? Change them back to Cubic when done.

## Exercise 2 - Close and Reopen

**Objective:** Extend the timeline to support closing and reopening.

Currently the door only opens. Extend `ADoor`:

1. Add a `bool bIsOpen` check to `OnInteracted` — if the door is already open, call `OpenTimeline.Reverse()` to play the timeline backwards (closing the door). Update `bIsOpen` accordingly.
2. Re-enable the `UInteractableComponent` after the close timeline finishes (in `TimelineFinished`, check direction and re-enable).
3. Update the `InteractPrompt` text based on state: "Open Door" when closed, "Close Door" when open.

Build and test. The door should open on first E press and close on second E press.

**Note:** `FTimeline::IsReversing()` returns true when playing in reverse. Use it in `TimelineFinished` to determine which direction just completed.

## Exercise 3 - A Sliding Drawer

**Objective:** Prove you can apply timelines to translation, not just rotation.

Create a new C++ Actor class called `ADrawer`. Requirements:

1. A `UStaticMeshComponent` as root.
2. A `FTimeline SlideTimeline` driven by a `UCurveFloat`.
3. A `FVector SlideDirection` property (`EditAnywhere`), default `FVector(0, 50, 0)` (slides along Y axis by 50 units).
4. A `UInteractableComponent` so the player can open and close it.
5. `TimelineUpdate` lerps between the closed position and `ClosedPosition + SlideDirection * Value` using `SetRelativeLocation`.
6. Toggle open/close on repeated interaction, same as Exercise 2.

Create a new curve asset `C_DrawerSlide` with a quick ease-out (keyframes (0.0, 0.0) and (0.4, 1.0), cubic). Assign it to a Blueprint child. Place the drawer in the level next to the door and test.

**Reflect:** How many lines of code differ between `ADoor` and `ADrawer`? Which lines are identical? What does that tell you about the value of the timeline pattern?

## Exercise 4 - Build UNarrativeTriggerComponent

**Objective:** Implement the trigger side of the narrative system.

From scratch (without looking at the README):

1. Create `UNarrativeTriggerComponent` inheriting from `UActorComponent`.
2. Add a `DYNAMIC_MULTICAST_DELEGATE_OneParam` called `FOnNarrativeEvent` passing `FName EventId`.
3. Add `UPROPERTY(BlueprintAssignable) FOnNarrativeEvent OnNarrativeEvent`.
4. Add `UPROPERTY(EditAnywhere) FName DefaultEventId`.
5. Add `UFUNCTION(BlueprintCallable) void Fire(FName EventId)` that broadcasts `OnNarrativeEvent`.
6. Disable tick in the constructor.

Add a `UNarrativeTriggerComponent` to `ADoor`. In `ADoor::OnInteracted`, after starting the timeline, call `NarrativeTriggerComp->Fire(TEXT("DoorOpened"))`.

Build. In the Content Browser, select the Door Blueprint child. In the Event Graph, add `BeginPlay > Get NarrativeTriggerComp > Bind Event to On Narrative Event`. In the bound event, add a Print String showing the Event Id. Play and press E on the door. Confirm the event id prints.

## Exercise 5 - Build ANarrativeDirector

**Objective:** Implement the director side of the narrative system.

1. Create `FNarrativeEntry` as a `USTRUCT(BlueprintType)` with:
   - `FName EventId`
   - `TObjectPtr<USoundBase> AudioLine`
   - `FText DisplayText`
   - `bool bOneShot = true`
     All fields must be `UPROPERTY(EditAnywhere, BlueprintReadWrite)`.

2. Create `ANarrativeDirector` inheriting from `AActor`:
   - `TArray<FNarrativeEntry> NarrativeLines`, `EditAnywhere BlueprintReadWrite`.
   - `TSet<FName> FiredOneShots` (private, just `UPROPERTY()` for reflection).
   - `UFUNCTION(BlueprintCallable) void ReceiveEvent(FName EventId)` that:
      - Finds the matching entry in `NarrativeLines`.
      - Returns early if `bOneShot` and already fired.
      - Adds to `FiredOneShots` if one-shot.
      - Calls `OnNarrativeLine`.
   - `UFUNCTION(BlueprintImplementableEvent) void OnNarrativeLine(FName EventId, USoundBase* Audio, FText Text)`.
   - `static ANarrativeDirector* Get(UWorld* World)` using `GetAllActorsOfClass`.

3. Update `UNarrativeTriggerComponent::Fire` to also call `ANarrativeDirector::Get(GetWorld())->ReceiveEvent(EventId)` if a Director exists.

Build. Create a Blueprint child of `ANarrativeDirector`. Place it in the level. Add an entry to `NarrativeLines` with `EventId = "DoorOpened"` and a `DisplayText`. Implement `OnNarrativeLine` in the Blueprint to Print String the text. Press E on the door.

## Exercise 6 - Narrative Volume

**Objective:** Trigger narrative from player position, not interaction.

Create `ANarrativeVolume`:

1. A `UBoxComponent` as root with collision profile `"Trigger"`.
2. `FName EventId` (`EditAnywhere`).
3. `bool bFireOnce = true` (`EditAnywhere`).
4. `bool bHasFired = false` (private, no UPROPERTY needed).
5. Bind `OnComponentBeginOverlap` in `BeginPlay`.
6. In the callback, return early if not the player (use `ActorHasTag("Player")`) or already fired.
7. Set `bHasFired = true` and call `ANarrativeDirector::Get(GetWorld())->ReceiveEvent(EventId)`.

Add the tag `"Player"` to the player character Blueprint's **Actor > Tags** array in the Class Defaults.

Place an `ANarrativeVolume` in a doorway. Add a `NarrativeLines` entry in the Director Blueprint with `EventId = "RoomEntered"`. Walk through the volume. Confirm the event fires once and does not repeat.

**Bonus:** Add a second volume in a different room. Confirm each fires its own event independently.

## Exercise 7 - Integrating Audio

**Objective:** Play a sound when a narrative event fires.

1. Find any short audio asset in the engine content (search in the Content Browser with **Show Engine Content** enabled for `Starter_Music` or similar, or import a short `.wav` you have permission to use).
2. In the Director Blueprint, update the `OnNarrativeLine` implementation to call `Play Sound 2D` using the `Audio` pin from the event.
3. Assign the audio asset to the `Audio Line` field on a `NarrativeLines` entry.
4. Play. Trigger the event. Confirm the audio plays.

If you do not have an audio asset, use a Print String as a substitute and add a comment in the Blueprint noting where audio would go. The architecture is what matters.
